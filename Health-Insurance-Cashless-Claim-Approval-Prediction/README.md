# Health Insurance Cashless Claim Approval Prediction

A supervised machine-learning regression project that estimates the approved amount for a cashless health-insurance claim using patient, treatment, hospital, cost and policy information.

> **Important:** This is an educational portfolio prototype using a supplied case-study dataset. It is not an insurer's decision engine, a medical tool, a fraud detector, or a guarantee of reimbursement. Do not use it for real claim decisions.

## Business problem
Hospitals submit cashless claim requests and insurers approve an amount after considering patient risk, treatment severity, hospital context, documentation and policy conditions. This project explores whether historical claim attributes can help estimate `approved_amount`.

- **Target:** `approved_amount`
- **Task:** Regression
- **Dataset:** 5,000 rows and 41 columns in the supplied CSV
- **Evaluation:** MAE, RMSE and R² on a chronological holdout; model selection by expanding-window time-series cross-validation on training data only.

## Project workflow
1. Understand the business problem and variable definitions.
2. Inspect shape, data types, descriptive statistics, missingness and duplicates.
3. Investigate invalid values. Retain plausible high-value claims rather than automatically deleting IQR outliers.
4. Engineer row-level ratios and policy-pressure features.
5. Split chronologically before fitting imputers/encoders.
6. Compare Ridge, Decision Tree, Random Forest, Extra Trees and Gradient Boosting with cross-validation on the training portion.
7. Evaluate the selected model once on a later-date holdout.
8. Save a reusable preprocessing + model pipeline.
9. Use the Streamlit interface to submit a hypothetical claim and view an estimate.

## Modeling notes and limitations
- Preprocessing is fitted inside a scikit-learn Pipeline, avoiding full-dataset imputation/encoding leakage.
- Exact duplicate rows are removed. Repeated claim IDs are not automatically dropped; investigate them separately.
- Implausible age/BMI/co-pay values are set to missing and imputed from training data. Plausible extreme claim amounts are retained.
- IDs are excluded from predictors to reduce memorization.
- Features such as `hospital_historical_approval_rate` and `document_quality_score` must be verified as available at the exact time a prediction would be made. If calculated after adjudication, they cause target leakage and must be removed.
- A chronological split is more realistic than a random split when dates represent the deployment timeline. Check whether the date range and data-generation process support this assumption.
- A model trained on this dataset may learn synthetic or dataset-specific patterns. Validate on independent, real, authorized data before drawing operational conclusions.
- Feature importance is associational, not causal. Protected or sensitive attributes should be reviewed for fairness and necessity.

## Suggested future improvements
- Verify business definitions and timing of every feature with a domain expert.
- Add a grouped/time-aware validation design if patients or hospitals recur across periods.
- Compare predictions against explicit policy-rule baselines.
- Add residual diagnostics and subgroup error analysis.
- Add SHAP only after the baseline pipeline is stable.
- Add unit tests for feature engineering and inference schema.
